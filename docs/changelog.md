# Changelog

## 2026-11-25
- Opt-in game-data download (`--gamedata-fetch` / `$SCTELEMETRY_GAMEDATA_FETCH=1`, off by default; `sctelemetry/gamedata_hub.py`): reads the installed build from `<channel>/build_manifest.id` and fetches exactly that build's `game-ships` / `game-salvage` / `game-keybinds` JSON from the public voidput/sc-gamedata-dumps hub into `.tmp/gamedata/<channel>/`. Checks `_build`, `_schema`, and `build.json` size / sha256 when present; atomic writes; never another build. `--gamedata` disables it. Manual: `uv run python -m sctelemetry.gamedata_hub`. Report in `/api/ship` `gamedata.fetch`. Docs: [install.md](install.md), [telemetry/api-spec.md](telemetry/api-spec.md) §8.5.
- Ship capabilities: a vehicle's upstream `capabilities` object (coming in sc-gamedata) wins per key over the local derivation; `cargoKnown: false` -> cargo unknown. Cache version 4.
- Hub fetch re-downloads a dataset whose sha256 differs from the tag's `build.json` (tags get republished under the same name); `_build` only decides for tags without hashes. Manufacturer name/code prefer the dataset's `manufacturerName` / `manufacturerCode`. The salvage dataset's new `vehicles[]` list (34 on LIVE) feeds `salvage`. On both published tags, upstream and local capabilities give the same table (0 differences, PTU 1108 / LIVE 1104 classes).
- `/api/actions` entries carry `keybind` (game label, actionmaps, activation mode, default inputs) from `game-keybinds.json` (`sctelemetry/keybinds.py`); dashboard Controls buttons show it as a tooltip. Tests: `tests/test_gamedata_hub.py`, `tests/test_keybinds.py`.

## 2026-11-24
- PTU 5.0.202.35026 (CL 13273298) schema: additive only. New `FrameHeader`, `GameFrame` (+ `GameDebugInfo`: fps, ping, server fps, shard), `VehicleQuantumTravel`, actor location / tracked contract / CrimeStat / operator mode / player name; `quantum_fuel`, `altitude`, `VehicleState.health` now `optional`. Regenerated [telemetry/api-reference.md](telemetry/api-reference.md) (new `NOTES`; `player_name` redacted like `uec_balance`); version table in [telemetry/api-spec.md](telemetry/api-spec.md) §7. `--mock` fills the new fields when the resolved schema has them.
- Dashboard shows the new fields: Pilot panel gets operator mode + CrimeStat badges, a click-to-reveal player handle, location (hierarchy, jurisdiction, armistice) and tracked contract; Ship panel gets a QT badge and a quantum-travel block (state, spool/calibration, destination, ETA, remaining distance); new Game panel (state, menu, mode, frame seq, client/network/server debug stats). If `altitude` is missing the panel shows DEEP SPACE; if `quantum_fuel` is missing the meter shows `—`. Panels for fields an older schema lacks stay hidden. `--mock` no longer crashes on older cached schemas that have no `VehicleState.health`.
- Alert pop-ups can be turned off per browser: a header button switches pop-ups on/off, and the Alerts panel has a level picker (all / warning + / critical only / off), saved in localStorage. Alerts still go to the Recent list. Audio mute is unchanged. Logic in `AlertLogic.toastAllowed`, tested in `tests/test_dashboard_js.py`.
- On this build the game's gRPC service does not start (`No Star Engine services started`) with the previously working settings; documented in api-spec §2, cause open.

  - New `scgameapi/alerts.py` engine with rule kinds threshold (with hysteresis), transition, edge, composite and event. Rules support cooldown, debounce, `when` guards, `supersedes` and `on_entry`. The engine re-baselines on startup, on a vehicle change, after a stream gap and when a replay loops.

  - Audio plays in exactly one place: the newest sound-enabled dashboard tab (WebAudio tones plus Web Speech), otherwise the bridge (at the time `pw-play`/`paplay` with freedesktop sounds, plus piper, espeak-ng, espeak or spd-say; now cross-platform, see the entry above). Never both.
  - Dashboard: toasts (critical alerts stay until acknowledged), an Alerts panel (recent alerts, rule toggles, test buttons, mute 5/15/60 min, audio mode) and an **Enable sound** button.
  - API: `/api/alerts*` endpoints, named SSE `alert` events, `ALERT` hub events. CLI: `--alerts`, `--alerts-audio`, `--alerts-dry-run`.
  - Tests: `tests/test_alerts.py`, `tests/test_alerts_api.py`, plus the alert-logic tests in `tests/test_dashboard_js.py`.
  - Docs: [telemetry/alerts.md](telemetry/alerts.md) and api-spec §8.6.
- Alerts **review fixes**:
  - An exception in the alert engine no longer stops telemetry. Hub hooks are guarded, and a failing audio tick is logged once and skipped.
  - User-file settings are validated (types and ranges), and a non-object file falls back to the defaults instead of crashing the source.
  - `PUT /api/alerts/rules` keeps the user file's `settings`, persists omitted default ids as `removed`, and treats `null` as unset. `{rules: null}` gets a clean 400.
  - Message and speech templates are limited to known fields and simple format specs. `detail_re` is capped at 200 characters, and TTS argv ends options with `--`.
  - Toasts dedupe by `boot:id`, so they survive a bridge restart. A stopped bridge closes its SSE streams after 2 s.
  - The dashboard client id is per page load, so a duplicated tab gets its own id. Only the newest stream per id gets `play: true`. A tab must have its stream open to take the audio, and it claims the audio only when it is audible. Disabling sound is retried until confirmed.
  - A critical alert's preempt also cancels pending speech.
  - Speech uses `{pct_words}`. `health_low` is silent at death, gear speech is now "Gear down, overspeed", and test alerts carry sample fields.
  - Critical toasts clear after 60 s. **ACK ALL** and Escape clear all toasts, and phones show at most 3.
