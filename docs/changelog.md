# Changelog

## 2026-11-21 (cross-platform cleanup)
- **Windows + Linux support**: new `scgameapi/paths.py` finds the install per OS (`--sc-dir` / `$SC_DIR`, Windows drives + `%ProgramFiles%` + RSI Launcher log, Linux `$WINEPREFIX`, `~/Games/star-citizen`, `~/.wine`, `/mnt|/media|/run/media` Wine-prefix globs, macOS CrossOver) and picks the channel (`$SCGAMEAPI_CHANNEL`, else last played, else LIVE); used by schema, Game.log tailer and server. No machine-specific default paths in code; the schema error lists the searched paths.
- Ship capabilities: no home-dir `sc-gamedata` fallback; `--gamedata` / `$SCGAMEAPI_GAMEDATA` / `.tmp/gamedata/<channel>/` only.
- Alert audio: bundled WAV tones (`scgameapi/data/sounds/`, `scripts/gen_tones.py`) as fallback after the freedesktop sounds; players winsound (Windows) / afplay (macOS) / pw-play > paplay > aplay > ffplay (Linux) with a per-player format filter; Windows SAPI TTS via PowerShell with the text on stdin.
- Explicit UTF-8 (and LF) for every text file the code and tests read or write; Game.log rotation no longer relies on inode numbers on Windows, and one Windows poll reads at most 4 MB.
- Repo: `.gitattributes` (LF), wider `.gitignore`, CI on ubuntu-latest + windows-latest (`.github/workflows/ci.yml`), `scripts/run.sh` / `scripts/run.ps1`; README setup per OS with troubleshooting; personal paths removed from docs; the generated reference redacts `uec_balance`.

## 2026-11-21
- Fixed false "You died" alert: Game.log corpse item lines name no owner and also fire for players you kill nearby. Death/downed alerts now come from telemetry `ACTOR_DEAD`/`ACTOR_DOWNED`; the corpse rule is "Corpse nearby" (off by default). Docs corrected.
- **People/org lookup review fixes**: `You have joined` ⏎ `party` no longer creates a person named "party"; party body rules gated on their toast titles; circuit breaker (3 consecutive lookup errors pause like a 429); `parse_citizen` requires the handle and the lookup checks it matches; expired cache entries pruned (cap 2000); Clear cache wins over an in-flight lookup; queue no longer stops at the first 50 handles; parsers off the event loop with depth/entry/field caps; incomplete lookups cached 1 h as `partial`; `--mock` never contacts RSI.
- **People panel + RSI org lookup + Nearby ship info**: new `scgameapi/people.py` parses handle-bearing Game.log lines verified against 1.3 GB of LIVE/PTU logs (Vehicle Destroyed killer and id-mapped victim, QT calibration toasts, party toasts and party-launch lines, voice-channel owner and members, "started to QT to your current location"; self-only lines feed identity only) with a multi-line HUD toast joiner. Names are memory-only, behind **Show names** (`--show-names`, off by default) and the Origin/Host guard; never in `--record`, events or logs. Opt-in **Look up orgs** (`--lookup-orgs`) fetches public citizen pages (≥3 s apart, one in flight, 10 s timeout, fixed User-Agent), caches 7 days (404: 1 day) in `.tmp/rsi-cache.json` (0600, gitignored), backs off when blocked. API: `GET /api/people`, `PUT /api/people/settings`, `DELETE /api/people/cache`, `snapshot.people`. Nearby entries carry `info` (manufacturer, role, size, crew, cargo) from game data (shipcaps cache v3) and the dashboard explains `×N`. Tests: `tests/test_people.py` (synthetic lines, synthetic HTML fixtures, fake fetcher). Docs: [telemetry/people-and-lookup.md](telemetry/people-and-lookup.md), api-spec §8.7.
- **Alerts with sound and speech**:
  - New `scgameapi/alerts.py` engine with rule kinds threshold (with hysteresis), transition, edge, composite and event. Rules support cooldown, debounce, `when` guards, `supersedes` and `on_entry`. The engine re-baselines on startup, on a vehicle change, after a stream gap and when a replay loops.
  - 23 default rules in `scgameapi/data/alerts.default.json`, covering boost 25 % and empty, hydrogen, quantum, shields, faces (tuning-aware), hull, missile, hit and proximity MAJOR, oxygen, health, radiation, atmosphere, gear overspeed, G-load, armistice exit, shard join, QT arrival and corpse.
  - Audio plays in exactly one place: the newest sound-enabled dashboard tab (WebAudio tones plus Web Speech), otherwise the bridge (at the time `pw-play`/`paplay` with freedesktop sounds, plus piper, espeak-ng, espeak or spd-say; now cross-platform, see the entry above). Never both.
  - Dashboard: toasts (critical alerts stay until acknowledged), an Alerts panel (recent alerts, rule toggles, test buttons, mute 5/15/60 min, audio mode) and an **Enable sound** button.
  - API: `/api/alerts*` endpoints, named SSE `alert` events, `ALERT` hub events. CLI: `--alerts`, `--alerts-audio`, `--alerts-dry-run`.
  - Tests: `tests/test_alerts.py`, `tests/test_alerts_api.py`, plus the alert-logic tests in `tests/test_dashboard_js.py`.
  - Docs: [telemetry/alerts.md](telemetry/alerts.md) and api-spec §8.6.
- Alerts **review fixes**:
  - An exception in the alert engine no longer stops telemetry. Hub hooks are guarded, and a failing audio tick is logged once and skipped.
  - User-file settings are validated (types and ranges), and a non-object file falls back to the defaults instead of crashing the source.
  - `PUT /api/alerts/rules` keeps the user file's `settings`, persists omitted default ids as `removed`, and treats `null` as unset. `{rules: null}` gets a clean 400.
  - Message and speech templates are limited to known fields and simple format specs. `detail_re` is capped at 200 characters, and TTS argv ends options with `--`.
  - Toasts dedupe by `boot:id`, so they survive a bridge restart. A stopped bridge closes its SSE streams after 2 s.
  - The dashboard client id is per page load, so a duplicated tab gets its own id. Only the newest stream per id gets `play: true`. A tab must have its stream open to take the audio, and it claims the audio only when it is audible. Disabling sound is retried until confirmed.
  - A critical alert's preempt also cancels pending speech.
  - Speech uses `{pct_words}`. `health_low` is silent at death, gear speech is now "Gear down, overspeed", and test alerts carry sample fields.
  - Critical toasts clear after 60 s. **ACK ALL** and Escape clear all toasts, and phones show at most 3.
- **Live action state on buttons** + **ship capabilities**: `GET /api/action-states` (serves `scgameapi/data/action_state_map.json`), `GET /api/shield-faces` (new `scgameapi/data/shield_faces.json`), `GET /api/ship`, `GET /api/ships?class=X`, `snapshot.capabilities` from sc-gamedata (`scgameapi/shipcaps.py`, `--gamedata` / `$SCGAMEAPI_GAMEDATA`, cache `.tmp/ship-capabilities.json`, mtime reload). Dashboard: each mapped Controls button shows its state (lit / muted / N/A / NO SHIP / STALE, `?` for unverified, `UNSUPPORTED` + session N/A after door FAILED), operator modes gated by capabilities (`N/A · no mining`), Ship panel capability chips, Shields panel renders by face count (bubble / front-back / quadrants / 6-face / N segments, `DOWN` text). `--mock` fake triggers also flip gear and shield power. Tests: `tests/test_shipcaps.py`, `tests/test_dashboard_js.py` (node). Docs: [telemetry/action-state-map.md](telemetry/action-state-map.md), api-spec §8.5.
- Action-state review fixes: `capabilities.source` / `gamedata.source` is now a short label (`ptu/game-ships.json`), never the absolute path; `caps.cargo` is a bool plus new `caps.cargo_scu` (number | null; cache v2); N/A / no-cap state text uses the muted token (AA contrast); the focused / last-tapped button's notes show in a pinned line and via `aria-describedby` (touch-reachable); Refresh clears session `UNSUPPORTED` verdicts; hidden `--fake-fail REGEX` test switch.
